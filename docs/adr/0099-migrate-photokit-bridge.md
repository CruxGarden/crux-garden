# ADR 0099 — A bounded, read-only PhotoKit process bridge

Accepted November 10, 2026 within Daniel's authorized iCloud migration work. Current milestone includes the compiler-qualified bridge and fixture-qualified durable adapter, not a released iCloud connector.

Use Apple's public PhotoKit APIs in a small macOS Swift helper. The helper has no database, filesystem destination authority, network listener or credential handling. It returns bounded metadata pages and streams one explicitly identified resource through a private inherited pipe. The Node API remains the sole durable job, SQLite, fingerprint and destination owner. React remains injected-client and platform-independent.

Do not request authorization in this foundation. `hello` is pure capability negotiation; `status` queries the modern read/write access status without fetching assets. Discovery must refuse unless status is already authorized or limited, and it must never trigger an implicit request from undetermined status. Permission request/prompt identity must be qualified in the signed/native host before a connect action is exposed. The app does not launch the helper at startup or advertise a usable PhotoKit connector yet.

Use a bounded session snapshot with opaque resource handles. Explicit resource types retain original, current, alternate, adjustment and paired-video roles. Names are descriptive metadata, not output paths or identity. Resource size is unknown on supported older macOS releases; the existing shared job layer already supports unknown lengths and is reused (correcting the initial assumption that this had to be added). A metadata revision token detects observed asset changes but is not a provider content hash; never use it alone for content reuse.

Read incrementally with network access disabled unless explicitly supplied true for the selected read. Confirm the metadata revision before and after transfer. Successful completion is required even after all bytes appear; partial/error data must not be published. Node enforces framing, deadlines, byte bounds and cancellation by closing the session/process. A new session requires fresh discovery; no opaque handle is durable across restarts.

Compile test fixtures into a separate helper binary, never a runtime switch in the shipped helper. Fixtures exercise the real pipe codec, pagination, status gate, role separation, stream completion, failures and cancellation without a user's library. Build/package checks may invoke only `hello` on the production binary. Actual asset discovery and permission acceptance remain pending.

Reject private Photos SQLite/filesystem inspection, undocumented Apple web login, new SQLite owners, filename-only matching and automatically selecting every asset. Durable download integration now uses the existing collection worker under a trusted injected factory, absent from production host configuration. Stable selection IDs hash asset local ID, ordinal, type, original name and UTI; frozen revision detects observed changes. Duplicate identical resource descriptors are refused. Output paths are generated; original names and roles are retained as metadata. No transient helper key reaches SQLite or receipts. Restart rediscovers unfinished resources; completed destination bytes are rehashed.

Mark these items checksum-only for cross-job content reuse. Photos metadata revisions cannot supply that evidence, so comparison remains uncertain and a new job downloads again. Unknown-size summaries count unfinished unknown files and use measured bytes once complete. Host namespace/network choice are trusted configuration, not client input; native permission identity, source-binding lifecycle, album selection and real-library acceptance remain open before UI exposure.


The explicit host contract is now fixture-tested: optional MigrationClient.connectPhotos invokes a host action, which calls the in-process engine method after native confirmation. No request/HTTP command can reach the Photos factory, even when installed in a test host. SQLite maps hashed trusted source bindings to persistent UUID namespaces; this is bookkeeping, not proof of library/account identity. Source-binding lifecycle remains a native qualification item. Network intent is snapshotted per connection and never defaults to enabled. Production host/client registration remains absent. Static package inspection found no Photos usage string and only ad-hoc signatures, so prompt attribution/persistence cannot be claimed. Primary evidence and exact next acceptance live in monorepo docs/photos-host-qualification.md.
