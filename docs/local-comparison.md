# Selected local-file comparison

Decision recorded November 11, 2026 before implementation. The first slice compares an explicit file-set selection before preservation against the existing API-owned fingerprint catalog. It does not scan arbitrary directories or unpack archives, deduplicate storage, delete files, skip copies or change cloud comparison behavior. React remains host-injected; the Node API is the sole durable job/catalog owner.

The existing single preservation/review worker slot owns comparison lifetime. A separate bounded worker hashes selected source bytes and asks the API owner for up to 20 SHA-256/size candidates per file. The worker never opens SQLite. Catalog entries are hints: candidate bytes must be rehashed and equal both the stored and selected fingerprints before a matching location is reported. The source path itself is excluded. Names, sizes and timestamps alone are never content identity. A different matching path may still be a hard link; this is not proof of an independent backup.

Reads require canonical regular paths without symlink substitution and stable file identity, size and modification/change times across hashing. Source inventory is checked again before completion. A comparison is a dated observation; subsequent changes remain possible and normal preservation verification is unchanged. Missing, changed or unreadable candidates are counted separately. No match means no verified match among the bounded indexed locations checked, not that no duplicate exists anywhere. More than 20 catalog matches can hide a valid older location; the UI must state that search bound.

Bounds: 1–500 explicit files, 16 GiB per file, 64 GiB of combined source/candidate reads, 20 catalog candidates per source and 50 retained preview rows. Stream buffers remain bounded. Exceeding a read budget or final source-change check fails the whole comparison without partial results. An unreadable or missing source fails the whole comparison with an explicit error; no partial match summary is published. Pause and process restart discard partial results and restart hashing on retry. Source/selection changes clear the saved comparison. Existing jobs and fingerprint rows require no migration; the optional summary is saved with the job. No new filesystem grant or native permission is introduced.

Planned qualification: renamed equal content, same-name different content, unindexed and stale entries, self exclusion, unsupported modes, source changes, symlink refusal, read/preview bounds, pause/restart, host injection and packaged worker/API communication. Real personal libraries and maximum-scale performance remain unqualified.
